# 시리얼 형식 (팀 공통)

11/18 팀 확인판 + 지휘자 줄(COUNT·END·START) 추가. 리듬게임(`game/nabiya-garden`)과 모든 보드가 이 형식을 따른다.

## 공통 규칙

- 115200bps, 8N1. 한 줄에 메시지 하나, 쉼표 구분, 줄 끝 `\n` (`\r\n`도 됨).
- 공백 없이. 대문자.
- 사람이 읽는 로그·디버그 줄은 맨 앞에 `#`을 붙인다. 게임은 `#` 줄과 모르는 줄을 무시하고 로그 창에만 남긴다.
- 연결 구조(허브로 보드마다 PC 직결 / Uno가 모아서 한 줄)는 아직 미정이다. 게임은 포트 1~4개를 같은 파서로 합치므로 어느 쪽이든 형식은 같다.

## 보드 → PC

```
BEAT,<박번호>                          Uno: 곡 박자, 0부터 63까지 (펄스와 같은 순간)
COUNT,<n>                              Uno: 카운트 4 3 2 1 (펄스 없음). v1.0.5 게임은 무시
END  /  END,STOP                       Uno: 곡 끝 / 중간에 멈춤
MODE,DMA_ON  |  MODE,DMA_OFF           각 STM32: 이번 판 이름. 켤 때 한 번 + 바꿀 때마다
<악기>,<이벤트>,<음>,<세기>,<박번호>,<오차ms>[,<등급>]
```

| 칸 | 값 |
| --- | --- |
| 악기 | `W` 관악기, `H` 하프, `D` 드럼 |
| 이벤트 | `ON` 시작, `OFF` 끝(관악기 유지 표시용, 하프·드럼은 안 보내도 됨) |
| 음 | `DO RE MI FA SOL` / 드럼은 `KICK SNARE` |
| 세기 | 0~100 (하프는 0) |
| 박번호 | 기준이 된 박. 박자를 아직 못 받았으면 -1 |
| 오차ms | 박 대비, `+`면 늦음. 부호를 꼭 붙인다(`+12`, `-8`, `+0`) |
| 등급 | 선택. `P G B M`. 없으면 게임이 오차ms로 등급만 붙인다 |

예)

```
W,ON,MI,72,21,+12
H,ON,RE,0,22,-8,G
D,ON,KICK,88,22,-3
W,OFF,MI,0,22,+640
```

- 오차ms는 각 STM32가 잰다: Uno 펄스를 EXTI로 받은 시각과 연주를 감지한 시각을 같은 타이머로 뺀 값. USB 지연은 섞이지 않는다.
- Miss는 보내지 않는다. 게임이 채보를 알고 있어서, 판정 창 + 0.3초 안에 이벤트가 없으면 Miss로 표시한다.
- 같은 BEAT가 여러 포트에서 와도 게임은 한 번만 쓴다.

## PC → Uno

```
START            지금 템포로 시작 (기본 90 BPM)
START,<bpm>      템포를 정해서 시작 (60~140)
STOP             멈춤
```

게임 v1.0.5는 아직 `START`를 보내지 않는다(첫 BEAT를 기다렸다가 시작). v1.1에서 Space → `START,<고른 템포>`를 보낼 예정이다. 그 전에는 Uno의 D2 버튼이나 시리얼 모니터로 `START`를 보낸다.

## 박자 펄스 (Uno → 각 STM32, 선)

- Uno D8에서 박마다 10ms HIGH. 받는 쪽은 올라가는 순간(EXTI rising).
- 카운트 4박에는 펄스가 없다. BEAT,0 직전 2.2초 이상 펄스가 없도록 Uno가 맞춘다 → 받는 쪽은 "2초 넘게 쉬었다 오는 첫 펄스 = 0번 박"으로 세면 된다.
- 150ms보다 짧은 간격은 잡음으로 무시 권장.
- Uno는 5V, STM32는 3.3V: 받는 핀 앞에 1kΩ + 2kΩ 분압. GND 공통.
