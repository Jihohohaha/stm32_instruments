# 팀원 코드 확인 목록

하프·드럼 코드를 받으면 이 순서로 본다. 결과는 각 폴더의 `REVIEW.md`에 적는다(막을 것 / 사소한 것).

## 1. 시리얼 형식을 지켰나 (`docs/serial-protocol.md`)

코드만 읽지 말고, 보드를 굽고 시리얼 모니터로 실제 줄을 복사해서 본다. 그 줄을 게임의 로그 재생 창(L)에 붙여 넣으면 화면에 제대로 뜨는지도 바로 확인된다.

- [ ] 115200bps, 줄 끝 `\n`
- [ ] 악기 글자(`H`/`D`)와 음 이름(`DO RE MI SOL` / `KICK SNARE`)이 표 그대로인가 (소문자, `C4`, `DRUM1` 같은 다른 이름 X)
- [ ] 칸 수 6개(등급 쓰면 7개), 공백 없음
- [ ] 오차ms에 부호가 붙나 (`+0`, `-8`). `printf("%+ld")`가 newlib-nano에서 되는지 실제 출력으로 확인
- [ ] 박번호는 Uno 펄스로 센 값인가 (0부터, 박자 없으면 -1)
- [ ] 오차ms가 "가장 가까운 박 기준, +면 늦음"인가
- [ ] 세기 0~100 범위
- [ ] 디버그 줄은 `#`로 시작하나 (아니어도 게임은 무시하지만, 줄이 너무 많으면 USB 전송이 밀린다)
- [ ] 판(모드)을 바꿀 때 `MODE,DMA_ON` / `MODE,DMA_OFF`를 보내나

## 2. DMA 켜고 끄기를 제대로 했나

과제 채점 1순위가 "DMA를 쓴 이점을 숫자로"다. 비교가 공정해야 숫자가 의미 있다.

- [ ] 보드 B1(PC13) 같은 버튼으로 실행 중에 바꿀 수 있나 (다시 굽지 않고)
- [ ] OFF는 "DMA가 하던 일을 CPU가 직접"인가. 처리 함수·배열·타이머 주기·로그 설정이 두 모드에서 같아야 한다. OFF에서 샘플링 주기까지 바꾸면 공정한 비교가 아니다
- [ ] ON일 때 DMA를 레지스터로 직접 설정했나 (CCR·CNDTR·CPAR·CMAR, circular, 반/전체 완료 인터럽트). HAL_ADC_Start_DMA만 부르고 끝이면 레지스터 점수가 약하다
- [ ] 쓰는 DMA 채널이 겹치지 않나. F103은 ADC1 = DMA1 채널1만 된다. 관악기 소리는 DMA1 채널7(TIM4_UP)을 쓴다 → 보드가 따로라 겹칠 일은 없지만, 한 보드 안에서 두 기능이 같은 채널을 노리는지 본다
- [ ] 숫자를 내나: CPU 사용률(DWT CYCCNT), 놓친 샘플 수, 반 버퍼 간격 최소~최대. 관악기 v2의 `#STAT` 줄 형식과 맞추면 보고서 표를 한 번에 만들 수 있다
- [ ] 콜백과 메인 루프가 같이 쓰는 변수에 `volatile`
- [ ] 반 완료 콜백은 앞쪽 반, 전체 완료 콜백은 뒤쪽 반을 처리하나
- [ ] ADC 12비트 ↔ DMA 전송 폭 half-word(16비트)
- [ ] EXTI(박자 펄스) 인터럽트와 DMA 인터럽트 우선순위. 박자 시각을 재는 쪽이 밀리면 오차ms가 흔들린다

## 3. 아두이노(Uno 지휘자) 코드

`uno/conductor/conductor.ino` 기준. 팀원이 고친 판을 받으면 이것을 본다.

- [ ] 박 간격이 누적 오차 없이 계산되나 (`시작 시각 + k × 박 길이`. `delay(박 길이)` 반복은 박이 갈수록 늦어진다)
- [ ] 펄스 폭 10ms, 올라가는 순간이 박 시각, 펄스 뒤 바로 `BEAT,n`
- [ ] 카운트에 펄스를 내지 않나 (내면 STM32 박 번호가 4개 밀린다)
- [ ] `delay()`로 막지 않나 (막으면 `STOP`이나 시리얼 입력을 못 받는다)
- [ ] 5V 펄스가 STM32 핀으로 바로 가지 않나 (분압)
- [ ] I²C를 쓰게 되면: F103 I2C1 기본 핀 PB6이 관악기·드럼 소리 PWM(PB6)과 겹친다 → I2C1 리맵(PB8·PB9) 또는 I2C2(PB10·PB11). 3.3V ↔ 5V 레벨 변환
